# OpenPlayer v1.6.8

## Changes

- Windows native presentation supports hardware decoding with readback and
  respects the user's software decoding selection.
- Adds an isolated native presentation adapter that can consume upstream NR
  output while preserving the main video window, control overlay and media clock.
- Presentation supports optional HDR/Dolby Vision to SDR normalization and a
  drop-only input cap that does not duplicate slow upstream frames.
- Attempts NVIDIA `nvdec-copy` on the plugin's exactly matched GPU, falling back
  to software decoding when unavailable. Intel/AMD hardware-copy is not included.
- Decoding can be switched while paused; detach restores the output/device and
  retains the user's latest decoding choice. Active presentation reports the
  actual decoder rather than the requested mode.
- Retains 2x mode; no MFG or shared-texture extensions are added.

## Plugins And Limits

- XeFG is a separate optional Windows plugin, not bundled with the player. Use
  [XeFG 0.1.2](https://github.com/AreChen/openplayer-xefg/releases/tag/v0.1.2), which
  fixes indefinite black/frozen output when NR frames arrive late. Late frames
  are displayed without interpolation; timely frames resume 2x generation.
- DLSSNR 0.4.0 remains unchanged. On the tested 1080p60 source, use its 15 FPS
  processing cap for real-time NR plus XeFG. Uncapped NR can still overload and
  lose A/V synchronization; the late-frame fix does not increase NR throughput.
- Native plugins are trusted code. CPU frame transport is not GPU zero-copy;
  HDR conversion outputs SDR. Higher MFG ratios and shared textures are excluded.

## Verification

Verified with the installed XeFG 0.1.1 package on the explicitly selected second
RTX 3080 Ti: 1080p60 AV1 hardware-copy and software decoding, automatic attachment,
paused decode switching, seek/resume, resize/fullscreen, detach, process-crash
recovery and Alt+F4 cleanup. An unsupported raw-video codec uses software fallback.
The presenter test caps source delivery at 30 fps; this is not a 60-to-120 fps
performance claim. HDR/Dolby Vision hardware-copy has not been validated.

NR 0.4.0 plus XeFG 0.1.1 also passed on the same selected GPU with hardware-copy
decode: 12.018 seconds elapsed / 12.000 seconds media progression, 180 source and
179 generated frames at the existing 15 fps NR input cap. Paused NR updates,
detach/crash recovery and process cleanup passed. This short mpv clock sample
does not measure physical display/audio latency or long-session stability.

XeFG 0.1.2 additionally passed the reproduced uncapped NR liveness regression,
paused updates, window transitions, crash recovery and exit cleanup. With NR at
15 FPS, a 12-second sample produced 180 source plus 180 generated frames without
late fallback. This does not establish long-session or physical display latency.

enabled through the manual release workflow after separate validation.
